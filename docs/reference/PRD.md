# CiviSense: 제품 요구사항 명세서 (PRD)

## 1. 개요

### 1.1 프로젝트명
**CiviSense** — 민원 자동 분석 및 대응 시스템 (멀티 에이전트 + RAG + DB/대시보드)

### 1.2 배경 및 문제 정의
- 공공기관·고객센터에 접수되는 민원은 길고 복잡한 형식으로 작성되는 경우가 많음.
- 담당자가 수작업으로 일일이 검토·분류·응답 초안 작성은 시간과 인력 부담이 큼.
- 유사 과거 민원·처리 사례를 활용한 일관된 대응이 어려움.
- 긴급 민원의 신속한 식별·알림 체계가 부족한 경우가 있음.

### 1.3 목표
- **민원 문서 1건 입력** → 자동 요약·유형 분류·긴급도 판단·응답 문 생성·요약 기반 Q&A를 **멀티 에이전트 파이프라인**으로 일괄 처리.
- **RAG**로 유사 과거 민원·처리 사례를 검색해 응답 품질·일관성 향상.
- **DB 저장** 및 **관리자 대시보드**로 접수 이력·통계·상태 조회 및 알림 연동 기반 마련.

### 1.4 사용자
| 구분 | 설명 |
|------|------|
| **담당자(처리자)** | 민원 접수·검토·응답 작성·처리 완료 처리. 시스템이 생성한 요약·분류·응답 초안을 참고. |
| **관리자** | 전체 민원 통계, 유형별/긴급도별 현황, 대시보드·알림 설정. |
| **시스템** | 외부 알림(SMS/Email) 연동 대상(향후). |

## 2. 기능 요구사항

### 2.1 핵심 기능 (Must Have)

| ID | 기능 | 설명 | 비고 |
|----|------|------|------|
| F1 | **민원 문서 입력** | 텍스트(.txt) 또는 텍스트 paste로 민원 본문 입력. 파일 업로드 또는 폼 입력 지원. | |
| F2 | **문서 자동 요약** | 입력 민원을 구조화 요약(작성자 정보, 사건 개요, 요청 사항 등). | 에이전트: Summarizer |
| F3 | **민원 유형 자동 분류** | 요약·본문 기반으로 민원 유형 분류(예: 불편신고, 문의, 건의, 진정, 청구 등). 단일 또는 다중 유형 + 신뢰도. | 에이전트: Classifier |
| F4 | **긴급도 자동 판단** | 키워드·문맥 기반 긴급도 판단(긴급/보통/일반). 긴급 시 플래그 및 알림 연동 가능. | 에이전트: UrgencyDetector |
| F5 | **정중한 응답 문 생성** | 요약·유형·기관 컨텍스트를 반영한 정중한 응답 초안 생성. RAG로 유사 사례 참고 가능. | 에이전트: ResponseGenerator |
| F6 | **요약 기반 Q&A** | 저장된 민원 요약을 컨텍스트로, 사용자 질문에 대한 자연어 답변 생성. | 에이전트/기능: QnA |
| F7 | **민원 접수·이력 저장** | 민원 원문, 요약, 분류, 긴급도, 응답 초안, 상태를 DB에 저장. | |
| F8 | **관리자 대시보드** | 접수 목록, 유형별/긴급도별 통계, 상태별 필터, 상세 조회. | 프론트 + API |

### 2.2 부가 기능 (Should Have)

| ID | 기능 | 설명 |
|----|------|------|
| F9 | **유사 민원 검색(RAG)** | 과거 민원·처리 결과를 벡터 검색으로 조회, 응답 생성 시 참고. |
| F10 | **기관별 응답 템플릿** | 기관/유형별 응답 톤·템플릿 설정 가능(설정 테이블 또는 프롬프트 보강). |
| F11 | **긴급 민원 알림** | 긴급도가 높을 때 대시보드 배지·목록 강조, (향후) SMS/Email 훅. |

### 2.3 확장 (Could Have / Later)

| ID | 기능 | 설명 |
|----|------|------|
| F12 | **PDF/이미지 민원** | OCR 연동으로 PDF·이미지에서 텍스트 추출 후 동일 파이프라인 처리. |
| F13 | **실시간 SMS/Email 알림** | 긴급 민원 접수 시 외부 API 연동. |

## 3. 비기능 요구사항

| 구분 | 요구사항 |
|------|----------|
| **성능** | 민원 1건 기준 파이프라인 처리 목표: 30초 이내(LLM 호출 포함). |
| **가용성** | API 서버·에이전트 서버 장애 시 적절한 에러 메시지 및 재시도 정책. |
| **보안** | 민원 데이터 접근 권한 구분(담당자/관리자). API 인증(세션 또는 JWT). 개인정보 로깅 최소화. |
| **확장성** | 에이전트 노드 추가·순서 변경이 LangGraph 정의만으로 가능하도록 설계. |
| **운영** | 로그·에러 추적 가능. 환경 변수로 API 키·DB URL 등 설정. |

---

## 4. 성공 지표

- 담당자가 민원 1건당 검토·분류·응답 초안 작성 시간을 기존 대비 50% 이상 단축(목표).
- 민원 유형 분류 정확도(샘플 검수 기준) 85% 이상.
- 긴급 민원 누락률 0%에 수렴(규칙 + LLM 이중화).

---

## 5. 범위 외 (Out of Scope) — 1차 버전

- 실제 SMS/Email 발송 인프라 연동(인터페이스만 준비).
- 다국어 민원(1차: 한국어 중심).
- 실시간 동시 접속 대규모 부하 테스트.
